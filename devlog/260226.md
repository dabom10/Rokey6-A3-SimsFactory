## 1. 프로젝트 구조 및 전체 흐름

Isaac Sim 환경에서 Nova Carter AMR + UR10 매니퓰레이터를 통합한 도서관 자율 물류 로봇을 구현한다.

**Phase 1 — Pick & Place (기존 standalone)**
- 책 3권 (Red / Blue / Yellow) Spawn
- UR10 카메라로 색상 인식 → HSV 기반 분류
- 색상별 pick & place → KLT 박스 담기

**Phase 2 — AMR 웨이포인트 이동 + 책꽂기**
- Home → A(빨간 책) → B(노란 책) → C(파란 책) → Home
- 각 지점 도착 후 UR10으로 책장에 꽂기

**전체 State Machine:**
```
IDLE → MOVE_TO_PREGRASP → LOWER → ATTACH → LIFT → MOVE_TO_PLACE → DETACH → RETREAT
```

**시스템 계층 구조:**
```
┌──────────────────────────────────────────┐
│            Task Orchestration            │
│  (State Machine: IDLE→NAVIGATE→PICK→     │
│       PLACE→RETURN)                      │
├──────────────┬─────────────┬─────────────┤
│  Navigation  │  Perception │ Manipulation │
│   (Nav2/     │  (OpenCV)   │ (Isaac API)  │
│  Teleport)   │             │              │
└──────────────┴─────────────┴─────────────┘
```

## 2. 환경 변경 이슈 — Nova Carter 전환

### 🔴 USD 구조 변경에 따른 prim 경로 전면 수정

**발생 배경:**  
`environment_carter.usd`로 파일이 교체되고 Nova Carter를 도입하면서 USD 내부 prim 계층이 한 단계 깊어졌다. 기존 코드가 가정하던 경로가 모두 무효화됐다.

**변경 전 구조 (기존 코드가 가정):**
```
Root/robot/nova_carter/ur10/ee_link/...
```

**변경 후 실제 구조 (USD 진단 결과):**
```
Root/
  robot/           (Xform, Articulation: No)
    robot/         (Xform, Articulation: Yes  ← ArticulationRoot)
      nova_carter/
        ur10/
          ee_link/
            short_gripper/
              Camera
              suction_cup
```

중간에 `robot/robot`이라는 동일한 이름의 prim이 추가된 것이 핵심이었다.

**수정 내용:**
```python
# 변경 전
ROBOT_ARTICULATION_ROOT = "/Root/robot/nova_carter"
UR10_PRIM_PATH          = "/Root/robot/nova_carter/ur10"
EE_LINK_PATH            = "/Root/robot/nova_carter/ur10/ee_link"
CAMERA_PRIM_PATH        = "/Root/robot/nova_carter/ur10/ee_link/short_gripper/Camera"

# 변경 후
ROBOT_ARTICULATION_ROOT = "/Root/robot/robot"
EE_LINK_PATH            = "/Root/robot/robot/nova_carter/ur10/ee_link"
CAMERA_PRIM_PATH        = "/Root/robot/robot/nova_carter/ur10/ee_link/short_gripper/Camera"
```

커밋에서는 경로 상수 3개 수정(`/Root/robot/nova_carter` → `Root/robot/robot/nova_carter`)으로 반영됐다.

**💡 핵심 교훈:** USD 파일을 수정할 때마다 standalone 코드의 모든 하드코딩된 prim 경로가 무효화될 수 있다. 진단 스크립트(`stage_diagnostics_result.txt`)를 항상 먼저 실행하는 습관이 필요하다.

## 3. Articulation 구조 이슈 — `SingleManipulator` → `SingleArticulation`

### 🔴 ArticulationRoot 위치 혼동

**에러:**
```
Failed to find articulation at '/Root/robot/robot/nova_carter/ur10'
Pattern '/Root/robot/robot/nova_carter/ur10' did not match any rigid bodies
AttributeError: 'NoneType' object has no attribute 'is_homogeneous'
```

**원인:**  
`ur10`은 독립된 ArticulationRoot가 아니다. Carter AMR + ur10이 `/Root/robot/robot` 하나의 ArticulationRoot로 통합되어 있는 구조다. `SingleManipulator`는 넘기는 `prim_path` 자체가 ArticulationRoot여야 하는데, `ur10` 경로를 넘기면 physics tensors가 articulation을 찾지 못하고 `None`을 반환한다.

**해결:**  
`SingleManipulator` → `SingleArticulation`으로 교체하고, 실제 ArticulationRoot인 `/Root/robot/robot` 전체를 등록한다. ur10 제어는 전체 DOF 중 joint 이름으로 인덱스를 찾아 `joint_indices`로 subset 전달하는 방식으로 처리한다.

```python
# 변경 전
from isaacsim.robot.manipulators import SingleManipulator
self.ur10 = self.world.scene.add(
    SingleManipulator(prim_path=UR10_PRIM_PATH, ...)  # ur10 경로 → 에러
)

# 변경 후
from isaacsim.core.prims import SingleArticulation
self.robot_art = self.world.scene.add(
    SingleArticulation(prim_path=self.robot_articulation_root, ...)  # /Root/robot/robot
)
self.ur10_indices = [self.robot_art.get_dof_index(n) for n in self.joint_names]
```

확인된 ur10 DOF 인덱스 (Carter 전체 articulation 기준):

| Joint | DOF Index |
|---|---|
| shoulder_pan_joint | 0 |
| shoulder_lift_joint | 1 |
| elbow_joint | 2 |
| wrist_1_joint | 3 |
| wrist_2_joint | 7 |
| wrist_3_joint | 10 |

wrist_2, wrist_3의 인덱스가 불연속인 이유는 Carter 바퀴 joint들이 중간에 섞여 있기 때문이다.

**💡 핵심 교훈:** 여러 로봇이 하나의 USD에 통합된 경우, 진단 결과에서 `Articulation` 컬럼이 `Yes`인 prim이 ArticulationRoot다. 통합 articulation에서 일부 joint만 제어할 때는 `SingleArticulation` + `joint_indices` subset 방식을 사용해야 한다.

## 4. ROS2 Bridge 이슈

### 🔴 standalone 모드에서 ROS2 토픽 미발행

**현상:**  
ActionGraph는 ACTIVE이지만 `ros2 topic list`에 `/odom`, `/scan`, `/cmd_vel` 등이 나타나지 않음. 반복 경고 출력:
```
Could not find node type interface for 'isaacsim.ros2.bridge.ROS2Context'
Could not find node type interface for 'isaacsim.ros2.bridge.ROS2SubscribeTwist'
```

**원인:**  
Isaac Sim standalone 실행 시 ROS2 bridge extension은 기본으로 로드되지 않는다. 설치(`~/isaacsim/exts/isaacsim.ros2.bridge`)는 되어 있으나 런타임에 로드가 안 된 상태.

**시도한 방법들:**

| 방법 | 결과 |
|---|---|
| `extra_extensions` 옵션 추가 | 효과 없음 |
| `python.sh --ext-folder --enable` 옵션 | Kit 옵션 미지원으로 실패 |
| extension manager 직접 활성화 | **채택 성공** |

**최종 해결 (채택):**
```python
simulation_app = SimulationApp({"headless": False})

import omni.kit.app
omni.kit.app.get_app().get_extension_manager().set_extension_enabled_immediate(
    "isaacsim.ros2.bridge", True
)
```

실행 시 반드시 ROS2 환경 소싱 후 실행:
```bash
source /opt/ros/humble/setup.bash && \
  ./python.sh /home/rokey/Rokey6-A3-SimsFactory/project/standalone_first_ver.py
```

커밋 메시지 `[pnp] - ros2 통신 안됨: SimulationApp에 ROS2 bridge 활성화 추가`에 해당하는 이슈다.

## 6. TF 타임스탬프 이슈 — Nav2 연동 핵심 장벽

### 🔴 `TF_OLD_DATA` — timestamp 0 문제 (가장 핵심 이슈)

**증상:**
```
TF_OLD_DATA ignoring data from the past for frame base_footprint at time 0.000000
according to authority Authority undetectable
```

`/tf` 토픽 echo 결과:
```
stamp: sec: 861   ← ros2_publish_raw_transform_tree (정상)
stamp: sec: 0     ← ros2_publish_transform_tree (문제)
```

**원인:**  
`ActionGraph_tf_odom` 내부의 `ros2_publish_transform_tree` 노드에  
`inputs:timeStamp`가 `isaac_read_simulation_time`의 `outputs:simulationTime`과  
**연결되지 않아** timestamp가 0.0으로 고정된 채로 TF가 publish됨.

동일 그래프의 `ros2_publish_raw_transform_tree`, `ros2_publish_odometry`, `ros2_publish_clock`은 정상 연결되어 있었으나 `ros2_publish_transform_tree`만 누락된 상태였다.

```
ActionGraph_tf_odom 연결 상태:
  ros2_publish_clock              ← simulationTime ✅
  ros2_publish_odometry           ← simulationTime ✅
  ros2_publish_raw_transform_tree ← simulationTime ✅
  ros2_publish_transform_tree     ← simulationTime ❌  (오늘 발견)
```

**Nav2에서 timestamp=0 TF가 문제인 이유:**  
Nav2는 `use_sim_time: true` 상태에서 `/clock`(sec: 778~)과 비교하여 해당 TF를 "과거 데이터"로 판단하고 자동으로 무시한다. 이 때문에 `base_link`, `wheel_left`, `wheel_right` 등 URDF 기반 TF가 모두 동작하지 않게 된다.

**진단 방법 (Script Editor에서 전수 점검):**
```python
import omni.graph.core as og
graph = og.get_graph_by_path("/Root/robot/robot/ActionGraph_tf_odom")
for node in graph.get_nodes():
    for attr in node.get_attributes():
        if 'timeStamp' in attr.get_name() or 'simulationTime' in attr.get_name():
            print(node.get_prim_path(), attr.get_name(), attr.get())
```

**해결 방법 (Script Editor에서 연결 직접 추가):**
```python
import omni.graph.core as og
graph = og.get_graph_by_path("/Root/robot/robot/ActionGraph_tf_odom")
sim_time_node = graph.get_node("/Root/robot/robot/ActionGraph_tf_odom/isaac_read_simulation_time")
tf_node = graph.get_node("/Root/robot/robot/ActionGraph_tf_odom/ros2_publish_transform_tree")
tf_node.get_attribute("inputs:timeStamp").connect(
    sim_time_node.get_attribute("outputs:simulationTime"), True)
print("완료")
```

### 🔴 `childFrameId` 불일치 — `base_link` vs `base_footprint`

**증상:**  
Isaac Sim OmniGraph의 `ROS2 Publish Raw Transform Tree` 노드에서 `childFrameId = base_link`로 설정되어 있었으나 Nav2는 `base_footprint`를 요구한다.

**해결:**  
`childFrameId`를 `base_link` → `base_footprint`로 수정하고, `nav2_params.yaml` 전체에서 `base_frame_id`, `robot_base_frame` 파라미터를 `base_footprint`로 통일했다.

| 파라미터 | 원본 | 수정 | 이유 |
|---|---|---|---|
| `base_frame_id` (전체) | `base_link` | `base_footprint` | Isaac Sim TF 루트 프레임 |
| `robot_base_frame` (전체) | `base_link` | `base_footprint` | 동일 |
| `odom_topic` | `chassis/odom` | `odom` | Isaac Sim publish 토픽 |
| `scan_topic` | `/front_3d_lidar/scan` | `/scan` | 2D 라이다 1개 구성 |
| `vx_max` | `0.5~0.8` | `0.22` | differential_controller 속도 제한 |
| `transform_tolerance` | `0.1~0.2` | `0.5` | TF 지연 여유 |

## 9. 네비게이션 알고리즘 이슈

### 🔴 로봇 방향 정렬만 하고 전진하지 않는 문제

**현상:**  
Pure Pursuit 알고리즘 적용 시 목표까지 45° 이상 각도 차이가 나면 회전만 100초 이상 지속하다 실패.

**해결 — 3단계 제어 알고리즘 채택:**
```
각도 > 28°: 회전만 (각도 정렬)
각도 > 5°:  회전 + 전진 (병렬 제어)
그 외:      전진만 (목표 도달)
```

**좌표계 문제:**  
Isaac Sim 좌표계와 ROS2 `/odom` 좌표계가 다르다. 로봇 제어 개발 시 좌표계를 먼저 명확히 정의하는 것이 필수다.

| 좌표계 | 로봇 위치 예시 |
|---|---|
| Isaac Sim | (-10.13, 6.21) |
| ROS2 /odom | (0, 0) 근처 (오도메트리 기준 상대값) |

## 10. 매니퓰레이션 이슈

**현상 (커밋 메시지 `[1차 통합] - phase 2 넘어갈 때 큐브 떨궈지는 문제`):**  
Phase 1 완료 후 Phase 2에서 `teleport_robot()`을 호출하면 로봇만 이동하고 KLT 박스 안의 책들은 원래 위치에 남아 낙하하거나 흩어진다.

**원인:**  
책 prim이 `/Root` 하위에 독립적으로 존재하므로 로봇 teleport와 무관하다.

**해결 — `reparent_with_world_pose()` 구현:**  
USD 씬 그래프에서 자식 prim은 부모의 transform을 상속한다. 책을 `/Root/robot` 하위로 reparent하면 로봇 teleport 시 자동으로 함께 이동한다.

```python
def reparent_with_world_pose(stage, src_path, dst_parent_path):
    # 1. 현재 world matrix 저장
    world_m = get_world_matrix(stage, src_path)
    # 2. prim 이동 (경로 변경)
    omni.kit.commands.execute("MovePrim", path_from=src_path, path_to=new_path)
    # 3. 새 parent의 world matrix 계산
    parent_world_m = get_world_matrix(stage, dst_parent_path)
    # 4. local = world * parent_inv
    local_m = world_m * parent_world_m.GetInverse()
    # 5. 이동된 prim에 local transform 재설정
    xf = UsdGeom.Xformable(stage.GetPrimAtPath(new_path))
    xf.ClearXformOpOrder()
    xf.AddTransformOp().Set(Gf.Matrix4d(local_m))
    return new_path
```

**전환 흐름:**
```
Phase 1 완료 (책 3권 KLT 박스)
  → attach_books_to_robot()   (책 3권 → /Root/robot 자식)
  → teleport Home             (로봇 + 책 함께 이동 ✓)
  → A 직전: detach("red")     (red만 /Root 복귀)
  → A 도착 → 빨간 책 꽂기
  → B 직전: detach("yellow")
  → B 도착 → 노란 책 꽂기
  → C 직전: detach("blue")
  → C 도착 → 파란 책 꽂기
  → Home 복귀
```

### 🔴 `xformOp:orient` PrecisionFloat / Double 충돌

**에러:**

```python
existing_ops = xformable.GetOrderedXformOps()
for op in existing_ops:
    if op.GetName() == "xformOp:orient":
        if "double" in str(op.GetPrecision()):
            op.Set(Gf.Quatd(...))
        else:
            op.Set(Gf.Quatf(...))
```

## 13. 오늘의 핵심 인사이트

### Isaac Sim + ROS2 통합

1. **Isaac Sim은 Play 상태여야 TF가 퍼블리시된다.** Stop 상태에서는 `Simulation Time`이 0으로 고정된다.

2. **`use_sim_time: true` 환경에서 모든 TF의 timestamp가 `/clock`과 동기화되어야 한다.** `/clock`보다 오래된 timestamp의 TF는 Nav2가 자동으로 무시한다. stamp: 0인 TF는 사실상 동작하지 않는다.

3. **OmniGraph 노드 연결 시 `Exec In`과 `Timestamp` 모두 확인 필수.** 연결이 시각적으로 되어 있어도 실제 값이 전달되지 않는 경우가 있다. Property 패널에서 실제 값 변화 여부를 직접 확인해야 한다.

4. **standalone 모드와 GUI 모드는 동작이 다르다.** GUI 아이콘 상태, Stage 패널 등이 업데이트되지 않으므로 실제 상태는 코드 내 로그로만 확인해야 한다.

5. **ROS2 bridge는 standalone에서 자동 로드되지 않는다.** `SimulationApp` 생성 직후 extension manager로 활성화해야 한다.

### USD 및 Articulation 구조

6. **USD 파일 수정 후 가장 먼저 prim 경로를 의심하라.** 진단 스크립트를 항상 준비해두면 빠르게 확인할 수 있다.

7. **USD XformOp는 타입을 절대 바꾸지 말 것.** `ClearXformOpOrder()` 남발은 기존 타입 정보를 날려 재생성 시 충돌을 일으킨다.

8. **USD 씬 그래프의 parent 상속 구조를 적극 활용하라.** reparent + world pose 재계산 패턴은 물리 제어가 어려운 상황에서 매우 유용하다.

### 설계 원칙

9. **Fake Grasp(Parenting 방식)은 실용적인 선택이다.** 물리 기반 grasp보다 불안정성이 적고 State Machine을 명확하게 설계할 수 있다.

10. **SLAM보다 Static Map이 빠른 프로토타입에 적합하다.** SLAM까지 구현하는 것은 시간 대비 효율이 낮고, 통합 데모에서는 `map_server` + `AMCL` Static Map 방식이 훨씬 안정적이다.

11. **간단한 알고리즘이 항상 승리한다.** Pure Pursuit(복잡) → 실패. 3단계 각도-속도 제어(단순) → 성공.
