## 💡 핵심 인사이트 (Key Insights)

### 1. Articulation 트리 통합의 원칙
Isaac Sim에서 복합 로봇(모바일 베이스 + 팔 + 그리퍼)을 구성할 때는 **반드시 단일 Articulation Root** 아래 모든 링크가 종속되어야 한다. 부품을 USD에 붙일 때마다 `RigidBodyAPI`와 `ArticulationRootAPI`의 존재 여부를 확인하고, 중복 PhysicsScene은 즉시 제거해야 한다.

### 2. 라이다/센서 하우징 설계 시 주의사항
센서를 메쉬로 감쌀 때, **센서의 origin(원점)이 하우징 메쉬 내부에 갇히면** 레이캐스트가 자신의 껍데기를 먼저 맞춰버려 의도치 않은 Occlusion이 발생한다. 하우징 메쉬는 센서 원점 기준으로 충분히 크게, 혹은 Collider를 끄는 방식으로 설계해야 한다.

### 3. 좌표계 혼동 (Local vs World)
Isaac Sim 개발에서 가장 빈번한 실수 중 하나다.
- **UI Property 창에서 보이는 값 = Local(부모 기준 상대) 좌표**
- **`get_world_pose()`로 가져온 값 = World(절대) 좌표**
- RMPFlow 컨트롤러에 타겟을 넘길 때는 World 좌표를 사용해야 한다.
- 두 좌표계를 혼용하면 로봇이 허공을 더듬거리거나 반대편으로 날아가는 현상이 발생한다.

### 4. Physics Bouncing 방지 패턴
USD의 정적 속성(Xform, Joint Position)을 강제로 변경한 뒤 물리 엔진이 켜지면 순간 속도를 무한대로 계산해 충격(Spike)이 발생한다. 안정화 루프 패턴으로 방지한다:

```python
# 안정화 루프 패턴 (약 60프레임)
for _ in range(60):
    robot.set_joint_velocities(np.zeros(robot.num_dof))
    world.step(render=True)
```

### 5. 디버깅은 로그가 전부다
시뮬레이션에서 로봇이 안 움직이거나 엉뚱한 곳으로 갈 때 눈으로만 봐서는 절대 원인을 알 수 없다. 최소한 다음 6가지 값을 1초마다 출력해야 한다:

```
[DEBUG] Target World Pos  : (x, y, z)
[DEBUG] Robot Base Pos    : (x, y, z)
[DEBUG] Current EE Pos    : (x, y, z)
[DEBUG] RMPFlow Target Joints : [...]
[DEBUG] Current Joints    : [...]
[DEBUG] Joint Error       : [...]
```

### 6. USD 파일 열기 방식의 중요성
`add_reference_to_stage()`로 환경 USD를 붙이면 Multi-root 구조가 망가지거나 Action Graph가 손실될 수 있다. 환경 파일은 **`open_stage()`로 직접 열어** 원본 구조를 100% 보존하는 것이 안전하다.

## 🛞 Action Graph (cmd_vel → 바퀴 구동) 작업 — 진행 중 🟡

### 목표
ROS 2 Nav2 스택에서 발행되는 `/cmd_vel` 토픽을 Isaac Sim 내부의 Action Graph가 수신하여, AMR 차체의 바퀴(Differential Drive)를 실제로 구동시키는 연결 고리 완성.

### 현재 상태
튜토리얼을 참고하면서 Action Graph를 구성하는 단계. 아직 완전한 동작 확인은 하지 못한 상태.

### Action Graph 구성 개요
Isaac Sim에서 `/cmd_vel`을 받아 바퀴를 구동하려면 다음 노드들을 연결해야 한다:

```
[ROS2 Subscribe Twist]
        ↓  (linear.x, angular.z)
[Differential Controller]
        ↓  (left/right wheel velocity)
[Articulation Controller]
        ↓
[실제 바퀴 Joint 구동]
```

| 노드 | 역할 |
|------|------|
| `ROS2 Subscribe Twist` | `/cmd_vel` 토픽 수신 (geometry_msgs/Twist) |
| `Isaac Differential Controller` | linear/angular velocity → 좌우 바퀴 각속도 변환 |
| `Isaac Articulation Controller` | 계산된 Joint Velocity를 로봇에 적용 |

### 주요 설정값 (튜닝 필요)
- **Wheel Radius:** 차체 바퀴 반지름 (USD에서 확인 필요)
- **Wheel Base:** 좌우 바퀴 간격 (USD에서 확인 필요)
- **Joint Names:** USD 트리에서 실제 바퀴 Joint 이름과 정확히 일치해야 함

### 알려진 주의사항
- Action Graph의 `Articulation Controller`에 연결할 Joint 이름이 USD 내 실제 Joint 이름과 **대소문자 포함 완전히 일치**해야 한다. 조금이라도 다르면 조용히 실패한다.
- 바퀴 Joint의 Drive 설정이 **Velocity 모드** (Stiffness=0, Damping>0)로 되어 있어야 `cmd_vel`이 의도대로 반영된다. Position 모드로 되어 있으면 바퀴가 특정 각도로 잠겨버린다.
- Action Graph는 **Play 버튼을 누른 이후**에만 동작한다. Play 이전에 `/cmd_vel`을 발행해도 반응 없음.
